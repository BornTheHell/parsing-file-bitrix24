# Инструкция по переносу на выделенный сервер

## Главное, что нужно понять перед началом

Приложение хранит своё "состояние" в 4 локальных JSON-файлах прямо в папке проекта:

| Файл | Что хранит |
|---|---|
| `tokens.json` | Токен доступа к Битриксу (`AUTH_ID`) и токен для его обновления (`REFRESH_ID`) |
| `known_chats.json` | Список из 1438 сделок с найденными чатами (результат `/full-scan`) |
| `cursors.json` | По каждому чату — ID последнего обработанного сообщения (чтобы не дублировать файлы) |
| `attached.json` | Локальный журнал уже прикреплённых файлов (доп. защита от дублей) |

**Эти файлы должны переехать на сервер ВМЕСТЕ с кодом.** Если перенести только `server.js` и `package.json`, а эти 4 файла не скопировать — приложение стартует "с нуля": попросит заново пройти установку в Битриксе и заново запускать `/full-scan`, теряя весь прогресс по курсорам (это не критично для работы, но лишний шаг, которого можно избежать).

Хорошая новость: **обновлять что-либо в настройках приложения в Битриксе (пути установки/обработчика) не требуется**, если переносим готовые токены — обновление `AUTH_ID` через `REFRESH_ID` идёт напрямую на `oauth.bitrix.info` и не зависит от того, какой URL сейчас прописан в приложении. Путь установки нужен только если придётся когда-нибудь переустанавливать приложение заново.

## Шаг 1. Собери файлы для переноса

На своём Windows-компьютере, в папке проекта (`C:\Users\xyu\Documents\bitrix\perehvat file` или как она у тебя называется) должны быть:

```
server.js
package.json
tokens.json
known_chats.json
cursors.json
attached.json
```

Останови сервер (`Ctrl+C` в окне с `npm start`), чтобы файлы не менялись во время копирования, и упакуй всю папку в архив (zip) любым способом (правой кнопкой → "Отправить" → "Сжатая ZIP-папка").

## Шаг 2. Подготовка сервера

Понадобится:
- Доступ по SSH к серверу (Linux, обычно Ubuntu/Debian).
- Установленный Node.js (LTS-версия). Если не установлен:
  ```bash
  curl -fsSL https://deb.nodesource.com/setup_lts.x | sudo -E bash -
  sudo apt-get install -y nodejs
  ```
- Проверь версию:
  ```bash
  node -v
  npm -v
  ```

## Шаг 3. Загрузка файлов на сервер

Создай папку под проект:
```bash
mkdir -p /home/твой_пользователь/bitrix-sync
```

Загрузи архив на сервер (с локального компьютера, через `scp` или любой SFTP-клиент вроде WinSCP/FileZilla):
```bash
scp путь\к\архиву.zip твой_пользователь@IP_СЕРВЕРА:/home/твой_пользователь/bitrix-sync/
```

На сервере распакуй:
```bash
cd /home/твой_пользователь/bitrix-sync
unzip архив.zip
```

Убедись, что все 6 файлов на месте:
```bash
ls -la
```

## Шаг 4. Установка зависимостей

```bash
cd /home/твой_пользователь/bitrix-sync
npm install
```

## Шаг 5. Пробный запуск

```bash
node server.js
```

Ожидаемый вывод — сразу должно быть видно, что известные чаты подхватились:
```
Сервер запущен на http://localhost:5000
...
  Известных сделок с чатами: 1438
```

Если видишь именно это (а не "известных чатов пока нет") — перенос состояния прошёл успешно. Останови (`Ctrl+C`) и переходи к постоянному запуску.

## Шаг 6. Постоянный запуск через PM2 (чтобы работало без открытой консоли)

PM2 — менеджер процессов, который держит приложение живым, автоматически перезапускает при сбое и переживает перезагрузку сервера (в отличие от Windows, где нужно было держать открытым окно `npm start`).

Установи PM2 глобально:
```bash
sudo npm install -g pm2
```

Запусти приложение через PM2:
```bash
cd /home/твой_пользователь/bitrix-sync
pm2 start server.js --name bitrix-sync
```

Настрой автозапуск при перезагрузке сервера:
```bash
pm2 startup
```
(команда выведет ещё одну команду для копирования — выполни её)

Сохрани текущий список процессов, чтобы PM2 знал, что перезапускать после перезагрузки:
```bash
pm2 save
```

## Шаг 7. Проверка и просмотр логов

Посмотреть статус:
```bash
pm2 status
```

Посмотреть логи в реальном времени (аналог того, что ты видел в консоли Windows):
```bash
pm2 logs bitrix-sync
```

Остановить/перезапустить при необходимости:
```bash
pm2 stop bitrix-sync
pm2 restart bitrix-sync
```

## Важно про безопасность

Сейчас сервер слушает порт 5000 без какой-либо авторизации — любой, кто узнает адрес и порт, сможет дёрнуть `/poll-all`, `/test-deal` или `/full-scan`. На сервере (в отличие от временного ngrok-туннеля) это может быть доступно постоянно, поэтому:

1. **Не открывай порт 5000 наружу напрямую.** Приложению не нужен внешний доступ вообще, если ты не планируешь переустанавливать его в Битриксе (тогда понадобится `/install` доступный извне). Если внешний доступ всё же нужен — закрой файрволом всё, кроме нужного пути:
   ```bash
   sudo ufw allow from любой_твой_IP to any port 5000
   ```
   или настрой nginx как обратный прокси с базовой авторизацией (логин/пароль) перед этим портом.

2. **Секретный ключ приложения (`CLIENT_SECRET`) сейчас прямо в коде `server.js`.** Это нормально для личного использования, но при передаче кода куратору или в общий доступ — стоит вынести в переменную окружения. Могу отдельно это сделать, если понадобится.

## Что НЕ нужно делать

- Не нужно заново регистрировать приложение в Битриксе.
- Не нужно менять "Путь установки"/"Путь обработчика" в настройках приложения.
- Не нужно заново запускать `/full-scan` — список из 1438 сделок уже перенесён вместе с `known_chats.json`.
- Не нужен ngrok — сервер теперь просто работает по своему постоянному IP/домену (если вообще нужен внешний доступ, см. пункт про безопасность выше).
